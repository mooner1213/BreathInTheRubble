# 게임 UI 현황과 제안 — 사용자 피드백 대기

검토일: 2026-11-04. 기준: 저장소 최상위 `design.md` 0.1.1, 특히 5~10절과 12.3절. 실제 UI는 아직 수정하지 않았다.

## 판단

이 게임은 플레이 중 정보를 휴대폰, 짧은 상황 안내, 소리와 공간 변화로 전달하는 구성이 적합하다. 체험 전후와 일시정지에 공통 메뉴를 두고, 체험 중 화면을 차지하는 정보는 작게 유지하는 안을 제안한다.

## 확인한 현재 상태

활성 체험 씬 `Assets/_Project/Scenes/ConfinedPrototype.unity`를 Unity 편집 모드에서 읽기 전용으로 조사했다. 비활성 UI도 포함했다.

- 제품 UI Canvas는 스마트폰 아래의 World Space `Phone Interface Canvas` 하나다. 마우스용 GraphicRaycaster와 TrackedDeviceGraphicRaycaster가 있다.
- EventSystem은 `XR UI EventSystem` 하나이며 XRUIInputModule을 사용한다. 실제 헤드셋 조작 검증을 의미하지 않는다.
- 휴대폰에 손전등, SOS, 수신 상태, 배터리 수치와 아이콘이 있다.
- 긴급전화에 119 입력, 숫자판, 삭제, 통화/재시도/종료, 뒤로가기가 있다. 전화 상태는 대기·연결 중·수신 없음·잘못된 번호·연결됨이다.
- 표시 잔량 24% 이하에서 배터리 전체 아이콘/숫자가 빨갛게 바뀌고 닫을 수 있는 휴대폰 경고가 뜬다.
- 현재 문구는 `LIGHT`, `SOS`, `NO SERVICE`, `CALL 119`, `LOW BATTERY` 등 영어 중심이다. 사용 폰트는 `Inter-Regular SDF NoBackfaceCulling`이다.
- Noto Sans CJK KR 원본/TMP 자원과 재난 교육 공통 Theme/Prefab 묶음은 프로젝트 검색에서 확인되지 않았다. VR 템플릿의 Affordance Theme를 공통 메뉴 Theme로 간주하지 않았다.
- 현재 체험 씬과 프로젝트 전용 스크립트에서 시작 메뉴, 일시정지/설정, 자막, 상황 안내 패널, 결과 화면은 확인되지 않았다.
- PC Phone Test의 여진·다음 단계·머리 보호·배터리 테스트 버튼은 에디터 개발 도구다.

## 화면별 제안

| 항목 | 제안 내용 | 표시 시점/위치 | 우선순위 |
| --- | --- | --- | --- |
| 시작 화면 | 제목, `체험 시작`, `설정`, 착석 상태의 짧은 조작 설명. 실제 종료/복귀 경로가 있는 항목만 제공 | 눈뜨기 연출 이전, 별도 메뉴 공간 | 1차 |
| 일시정지 | `계속하기`, `설정`, `처음부터 다시`. 재시작은 확인창을 거침 | 메뉴를 호출했을 때 안정된 공간 위치 | 1차 |
| 설정 | 구현된 소리 음량, 글자 크기, 표시 위치 재정렬. 음성/자막 설정은 실제 콘텐츠 연결과 함께 노출 | 시작/일시정지에서 같은 설정을 공유 | 1차 |
| 휴대폰 화면 정리 | 기존 파손된 잠금 화면 유지. 공통 폰트와 한국어로 수신·배터리·손전등·긴급전화 상태를 정리 | 실제 휴대폰 화면 | 1차 다음 |
| 휴대폰 경고 | 24%의 빨간 배터리 유지. 짧은 한국어 경고, 확인/닫기, 긴급전화 버튼을 가리지 않는 배치 | 휴대폰 안에서만 | 휴대폰 정리와 함께 |
| 상황별 짧은 안내 | 첫 물체 접근/첫 여진 때 필요한 한 문장. 수행 후 숨김. 물병과 휴대폰 획득 순서를 강제하지 않음 | 물체 근처 또는 정면 아래 안정된 위치 | 2차, 안내 강도 피드백 필요 |
| 자막 | 실제 음성과 같은 내용/시점, 두 줄 이내를 기본으로 구성 | 음성이 나오는 구간만 정면 아래 | 음성 콘텐츠와 함께 |
| 체험 완료 | `체험 완료`, 구현된 기록의 짧은 요약, `다시 체험하기`. 연결된 메뉴가 있으면 복귀 제공 | 실제 구조/완료 이벤트가 확정된 뒤 | 종료 연출과 함께 |

일시정지에는 체험 시간, 여진, 먼지, 소리, 물체 사용의 정지/복원이 함께 필요하다. 머리와 손 추적은 계속 유지하고, 계속하기 시 잡은 물체가 튀지 않아야 한다. 메뉴 모양만 만들고 일시정지가 동작한다고 표시하지 않는다.

## 검토할 구체적 문구

시작 화면 초안:

> 잔해 속의 숨
>
> 앉은 자세로 체험합니다. 손이 닿는 물건을 직접 살펴보세요.
>
> [체험 시작]  [설정]

휴대폰 문구 초안:

- `LIGHT` → `손전등`, 켜진 상태는 `손전등 켜짐` 또는 상태 아이콘+문구.
- `SOS` → `긴급전화`.
- `NO SERVICE` → `수신 없음`.
- `CONNECTING...` → `119 연결 중…`.
- 연결 실패 → `연결되지 않았습니다. 수신 상태를 확인하세요.` + `다시 시도`.
- 연결됨 → `119 연결됨`. 실제 신고 접수 과정이 구현되기 전에는 `신고 접수 완료`로 바꾸지 않는다.
- 저전력 경고 → `배터리 부족 / 24% 남음` + `확인`. 기존 빨간 배터리는 유지한다.

상황 안내 초안:

- 아직 잡아보지 않은 가까운 물체에 `[현재 잡기 입력] 휴대폰 잡기` / `[현재 잡기 입력] 물병 잡기`.
- 첫 여진에서 보호 판정이 없을 때 `양손을 머리 옆으로 올리세요` 같은 게임 조작 안내를 짧게 제공.
- 입력 표시는 실제 바인딩에서 가져오며, 특정 헤드셋 버튼 이름을 고정하지 않는다.
- 상시 안내, 다음 단계 버튼, 배속/시간 조절은 체험 UI로 옮기지 않는다.

완료 화면은 우선 실제 연결 여부와 남은 배터리처럼 확인 가능한 값만 검토한다. 사용 시간·시도 횟수 등 추가 기록은 수집 기능을 연결한 후 제공한다. 점수·합격·실패 등급은 기본 제안에 포함하지 않는다.

## 문서와 구현의 차이

- `design.md` 12.3절은 머리 보호를 후속 구현으로 기록하지만 현재는 판정과 피격 효과가 연결되어 있다. 해당 안내를 넣을 수 있으며, 기준 문서에는 실제 구현 상태를 나중에 함께 갱신할 필요가 있다.
- 금속관은 잡을 수 있으나 배관 두드리기의 신호 판정은 확인되지 않았다. 성공 안내/평가 항목으로 확정하지 않는다.
- 물병에는 45%의 일정한 물 부피를 표시하는 시각화가 있다. 마시기·물 소모 게임 규칙은 확인되지 않아 `물 마시기`, 물 사용 기록을 현재 기능처럼 안내하지 않는다.
- Rescue 단계/이벤트는 있지만 실제 구조 장면, 신고 접수 대화와 완료 화면은 남아 있다. 단순 단계 전환을 구현된 구조/접수 과정 전체로 취급하지 않는다.
- 공통 폰트 Noto Sans CJK KR Regular는 확정 사항이다. 문서의 정확한 HEX, 크기, 배치 수치는 제안이므로 사용자 피드백과 실제 사용 거리 검토를 거쳐 적용한다.
- 공통 메뉴는 불투명한 어두운 패널/흰 글씨/청록 포커스를 출발점으로 삼는다. 작은 휴대폰에 일반 메뉴의 버튼 크기나 1.5m 표시 거리를 그대로 강제하지 않는다.

## 추천 순서와 피드백 항목

추천 순서: 공통 폰트/기본 스타일 준비 → 시작·일시정지/설정 → 휴대폰 한국어·상태 정리 → 필요한 순간의 짧은 안내 → 음성/구조 콘텐츠와 자막·완료 화면 연결.

피드백이 필요한 세 가지:

1. 안내 강도: 필요한 순간에만 짧게 / 처음에 자세히 / 직접 발견 위주.
2. 종료 방식: 완료+핵심 기록 / 완료만 / 상세 행동 기록.
3. 첫 UI 작업: 시작·일시정지 메뉴 / 휴대폰 정리 / 상황 안내.

사용자 피드백을 받은 뒤 선택한 항목의 구체적 시안을 제시하고 실제 UI에 반영한다. 이 검토에서는 씬·프리팹·게임 코드를 수정하거나 Play Mode를 실행하지 않았다.
